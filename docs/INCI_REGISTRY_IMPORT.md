# Импорт INCI-реестра

## Формат и происхождение

`data/inci-registry.json` — документ схемы `1.0`, а не простой массив. Он
содержит версию реестра, источник выгрузки и `sha256` именно импортированного
входного файла. Каждая запись хранит каноническое INCI-имя, только опубликованные
в источнике aliases и функции, `cas`/`restrictions` либо `null`, а также
`provenance` с идентификатором источника, строкой/референсом и тем, какие поля
действительно присутствовали в выгрузке.

`null` означает, что значение не было получено. Скрипт не угадывает CAS,
ограничения, даты, версии и ссылки на конкретные записи.

`data/inci-registry-local-additions.json` хранит отдельно ручные aliases и
неоднозначные suggestions. Они не копируются в импортированные aliases. У каждого
есть причина, дата добавления и статус review. `unreviewed` сохранен для прежних
ручных правил; он не превращается в подтвержденное свойство ингредиента.

Текущий начальный снимок мигрирован из старого нормализованного массива. Его
источник обозначен `third_party_mirror_legacy_snapshot`, не как запрос в CosIng:
дата/версия исходной выгрузки и построчные locators неизвестны и записаны `null`.
Исходный массив сохранен в `data/inci-registry.legacy-array.json`; первый
совместимый резервный реестр — `data/inci-registry.previous.json`.

## Импорт

Создайте source manifest с реальными данными о выгрузке:

```json
{
  "id": "supplier-export-2026-10",
  "type": "official_export",
  "url": "https://publisher.example/export.csv",
  "version": "2026-10",
  "exportedAt": "2026-10-01",
  "retrievedAt": null
}
```

Локальная, воспроизводимая загрузка:

```powershell
node scripts/import-cosing-inci-registry.js `
  --input=imports/source.csv `
  --source=imports/source-manifest.json `
  --retrieved-at=2026-10-02T09:00:00.000Z
```

URL можно использовать только явно, и он обязан точно совпадать с `source.url`
в manifest:

```powershell
node scripts/import-cosing-inci-registry.js `
  --url=https://publisher.example/export.csv `
  --source=imports/source-manifest.json `
  --retrieved-at=2026-10-02T09:00:00.000Z
```

После успешной проверки создаются:

- `data/inci-registry.previous.json` — предыдущий валидный документ;
- `data/inci-registry-import-report.json` — добавленные, удаленные и измененные
  канонические записи;
- `data/inci-registry.json` — новый реестр.

Новый документ строится и валидируется до любой записи. Затем JSON записывается
во временный файл и атомарно переименовывается. При неверном заголовке CSV,
нарушенной схеме или недопустимом текущем реестре запись и резервная копия не
изменяются.

Восстановление предыдущей совместимой версии:

```powershell
node scripts/restore-inci-registry-backup.js
```

Скрипт восстановления тоже валидирует резервную копию до записи. Для старого
array-архива сначала используйте `scripts/migrate-legacy-inci-registry.js` с
явными `--input`, `--output` и `--legacy-archive`.

## Правила импорта

- Объединяются только полностью одинаковые канонические имена. Разные формы
  растений, например `Hamamelis Virginiana Water`, `Leaf Extract` и
  `Bark/Leaf Extract`, остаются отдельными записями.
- Функции и aliases очищаются от точных дублей, но не от «похожих» названий.
  Fuzzy-объединение не используется.
- Отсутствующие столбцы отмечаются `not_available`, пустые значения при наличии
  столбца — `null`. Это разные состояния.
- Импортный источник и ручные дополнения не смешиваются. Изменять ручные aliases
  нужно отдельным reviewable изменением файла local additions.
- Данные реестра — справочные функции идентичности INCI, не оценка эффективности,
  качества сырья, риска или назначения готового продукта.
