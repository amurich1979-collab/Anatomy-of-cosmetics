# C10. Количественные данные, фотозащита и длительность

Статус документа: инженерный контракт версии 1.0.0. Он описывает допустимый прием данных и не содержит оценок конкретных товаров.

## Граница вывода

Число появляется в `formulaAssessment.quantitative[]` только из отдельной записи измерения, связанной одновременно с:

- конкретным объектом: ингредиентом, торговой смесью или готовым продуктом;
- `formulaId` и, если версия формулы известна, той же `formulaVersion`;
- источником и точным locator внутри источника;
- статусом основания: сообщение пользователя, заявление производителя или протокол испытания готового продукта.

Порядок INCI, типичный технологический диапазон, регуляторный максимум, название товара и исследование отдельного ингредиента не создают концентрацию данного продукта.

## Вход измерения

Измерения передаются в существующем envelope `evidence.product.measurements[]`; маршрут API не меняется.

```json
{
  "property": "SPF",
  "subject": { "kind": "finished_product", "id": "formula-id" },
  "value": { "kind": "lower_bound", "min": 50, "label": "50+" },
  "unit": "SPF",
  "basisStatus": "manufacturer_declared",
  "formulaId": "formula-id",
  "formulaVersion": "market/version",
  "source": {
    "name": "source title",
    "type": "official_brand_page",
    "url": "https://example.invalid/product",
    "locator": "label claim"
  }
}
```

Пример показывает структуру и домен-заглушку; это не запись товара и не подтвержденное значение.

## Доверие к источнику

| Вход | Результат |
| --- | --- |
| Значение из HTTP-клиента с любым заявленным статусом | `user_reported`, источник не проверен |
| Внутренне проверенная официальная карточка/этикетка | `manufacturer_declared`, не независимое испытание |
| Внутренне проверенный протокол готового продукта | `test_reported`; независимость лаборатории отдельно не подтверждена |
| Неизвестный тип источника или несовпадающая версия | статус не повышается либо запись отклоняется |

Флаг внутреннего доверия не читается из публичного request body. Его может передать только серверный вызов `analyzeComposition`; маршрут `/api/analyze` оставляет клиентские сведения в статусе `user_reported`.

## Объекты и свойства

- `concentration`: только `ingredient` или `trade_mixture`, единица `%`.
- `pH`: только `finished_product`.
- `SPF`, `UVA-PF`, `critical_wavelength`, `water_resistance`: только `finished_product`.
- `filter_spectrum`: только подтвержденный ингредиент, уже распознанный системой как UV-фильтр.
- `effect_duration`: только готовый продукт, с явным названием эффекта.
- `reapplication_interval`: инструкция повторного нанесения, а не доказанная длительность защиты.

Процент `trade_mixture` не переносится на ингредиент. Спектр фильтра хранится как отдельный Claim и не создает SPF/UVA-PF продукта. Показатели SPF не суммируются.

## Неизвестное и отклоненное

Без допустимого значения, источника, locator или совпадающего `formulaId` числовая запись не создается. Причина остается в `quantitativeDiagnostics.rejected[]`. Отсутствие данных представлено пустым массивом, а не нулем или диапазоном `0-100`.

`SPF 50+` хранится как нижняя граница 50 с исходной маркировкой, а не как точное измерение 50. Неверные единицы и значения вне технического домена отклоняются.

## Основания границ

- [Регламент ЕС 1223/2009, статья 19](https://eur-lex.europa.eu/eli/reg/2009/1223/oj/eng) используется только как источник о маркировке ингредиентов.
- [Рекомендация Комиссии 2006/647/EC](https://eur-lex.europa.eu/eli/reco/2006/647/oj/eng) различает заявления о солнцезащитном продукте и подтверждение его эффективности.

Эти документы не подтверждают конкретный товар и не являются заключением о соответствии требованиям рынка РФ.

## Ограничения реализации

- Модуль не загружает URL и не верифицирует документы самостоятельно.
- Production-адаптер проверенных протоколов и числовых данных пока не подключен.
- Пользовательское отображение нового блока относится к C12; C10 формирует API-снимок и историю.
- Предметная проверка правил специалистом и испытания конкретного продукта остаются внешними этапами.
