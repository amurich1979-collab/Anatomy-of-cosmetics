# Экспертное покрытие (T12)

## Что считается корпусом

Приоритет строится только по локально доступным составам, для которых есть
полный INCI и происхождение формулы. Демо-карточки, пустые карточки и списки
только активных ингредиентов исключаются. Проверка воспроизводится командой:

```powershell
npm.cmd run build:t12-report
```

На 2026-09-29 из 14 уникальных карточек требованиям отвечает одна формула:
Trixosil с полным INCI, считанным с пользовательской этикетки. Пять демо,
три списка `active_ingredients_only` и пять карточек без состава исключены.
Этот корпус непригоден для вывода о частоте ингредиентов на рынке. Он задает
только внутренний порядок следующей ручной проверки.

## Раздельные метрики

| Метрика | Результат | Что означает |
| --- | ---: | --- |
| Распознавание имени | 34/37 (91,89%) | Точное, alias или допустимое partial-сопоставление с локальным INCI registry |
| Source-backed объяснение | 2/34 (5,88%) | Есть отдельное утверждение со ссылкой; обе записи требуют предметной проверки |
| Предметно проверенное объяснение | 0/34 (0%) | Нет утверждений со статусом approved/verified |

Рост первой метрики не меняет вторую или третью. Функция из справочника не
является доказательством эффекта, риска, качества сырья или назначения продукта.

## Первая приоритетная партия

`data/expert-coverage-priority.json` содержит 25 первых компонентов. Все
ингредиенты встречаются один раз, поэтому равная частота разрешается средней
позицией в формуле и затем именем. Niacinamide имеет source-backed утверждение
со статусом `review_required`; остальные записи партии имеют
`insufficient_data`. Пустые `effects` и `riskAssessment.statements` сохранены
намеренно: пробелы не заполнены сгенерированным текстом.

Отдельно добавлено осторожное утверждение для Panthenol по первичному
исследованию конкретной многокомпонентной эмолентной формулы. Оно не попало в
первые 25 из-за позиции в единственной формуле. Эффект не приписывается одному
пантенолу, концентрация неизвестна, риск не установлен, статус `review_required`.

## Аудит старых 122 записей

Полный построчный результат находится в `audit/t12-expert-coverage.json`.

- 122/122 не имеют ссылок на источники.
- 122/122 содержат неподтвержденный числовой `quality_score`.
- 122/122 содержат неподтвержденный `evidence_level` и хотя бы одно доменное
  утверждение без источника.
- 7 записей содержат формулировки, требующие отдельной проверки на чрезмерное
  обещание.
- Машинно доказуемых пересечений `best_for`/`avoid_for` и alias-коллизий не
  найдено. Это не доказывает отсутствие смысловых противоречий: их должен
  проверять предметный специалист.

Старый файл остается источником имен/aliases и некоторых прежних эвристик, но
его эффекты, риски и баллы не публикуются движком как экспертные факты.

## Границы переноса

Утверждения теперь содержат обязательные `productForm`, `riskAssessment`,
`evidenceStatus`, условия и ограничения. Неизвестная форма или концентрация
дает `conditional`; конфликт формы дает `not_applicable`. Данные исследования
готовой формулы нельзя автоматически переносить на другой продукт, отдельный
ингредиент, лекарственную форму или юрисдикцию. CosIng используется как
информационный справочник; его наличие не означает разрешение вещества или
безопасность готового продукта.

## Следующий безопасный шаг

Сначала накопить набор реальных полных составов с датой, рынком и источником,
затем перестроить частотный приоритет. Для каждой следующей партии до 25
ингредиентов нужны первичные/официальные источники и предметное ревью. Записи,
для которых этого нет, остаются `insufficient_data`.
