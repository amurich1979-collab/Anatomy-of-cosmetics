# UX Report

## Цель

Сократить путь пользователя на мобильном экране от открытия сайта до анализа состава без изменения бизнес-логики, API, базы данных, авторизации и деплоя.

## Что убрано с первого мобильного экрана

- Полная длинная вводная шапка заменена коротким описанием.
- Кнопки навигации `Главная`, `Настройки`, `Войти` скрыты на мобильном первом экране.
- Примеры `Retinol`, `Glycolic Peel`, `SPF` скрыты на мобильном.
- Каталог скрыт с первого мобильного экрана.
- Профиль кожи, контекст и тревоги перенесены ниже в блок `Дополнительно`.

## Что перенесено

- Профиль кожи и список тревог перенесены в раскрываемый блок `Дополнительно`.
- Ручной состав оставлен ниже основных быстрых действий как запасной сценарий.
- Каталог оставлен в проекте, но на мобильном не занимает первый экран.

## Что добавлено

- Короткий мобильный первый экран по схеме:
  - `Анатомия косметики`
  - поиск по названию
  - фото состава
  - штрихкод
  - кнопка разбора
- Фиксированная нижняя кнопка `Разобрать состав`, доступная при прокрутке.
- Поле `Ввести штрихкод EAN/UPC`, которое использует существующий поиск по строке.
- Автопрокрутка к результату при запуске анализа и после успешного OCR фото.
- Мобильные стили для 360px, 390px и 412px.

## Сколько экранов до анализа

- По названию: 1 экран. Пользователь вводит название и нажимает фиксированную кнопку `Разобрать состав`.
- По фото: 1 экран для загрузки фото, затем сервис автоматически запускает разбор при уверенном выделении состава и прокручивает к результату.
- По штрихкоду: 1 экран. Пользователь вводит код, нажимает `Найти по коду`, затем запускается существующий разбор.

## Ограничения

- Реальное сканирование камерой штрихкода не добавлялось, чтобы не менять бизнес-логику и зависимости. Поле принимает EAN/UPC как текст или ввод со сканера клавиатурного типа.
- Каталог и расширенные настройки не удалены, только убраны с первого мобильного экрана.
- UI результатов не переписывался, оптимизация сфокусирована на пути до анализа.
