# T07: штрихкоды и допустимые QR

Дата: 28.09.2026. Выполнен только T07. Маршруты API, авторизация, Telegram, источники продуктов и деплой не изменялись.

## Что изменено

- Добавлен единый валидатор EAN-8, EAN-13, UPC-A и UPC-E с проверкой контрольной цифры GS1 до любого поиска товара.
- UPC-A и соответствующий EAN-13 с ведущим нулём обрабатываются как один идентификатор. В интерфейсе явно показывается исходный и нормализованный код. UPC-E разворачивается в GTIN-12, затем приводится к 13-значному поисковому представлению.
- Камера сначала использует нативный `BarcodeDetector`, но только если браузер объявляет поддержку всех нужных форматов: EAN-8, EAN-13, UPC-A, UPC-E и QR. Иначе используется локальный fallback ZXing.
- Добавлена отдельная кнопка «Загрузить фото кода». JPEG, PNG и WebP до 15 МБ декодируются тем же безопасным конвейером. Это не отправляет изображение внешнему AI/API.
- Fallback `@zxing/browser` 0.2.1 хранится локально в `public/vendor/zxing`, вместе с MIT- и Apache-2.0-лицензиями и SHA-256. Выбор сверялся с [официальной документацией ZXing Browser](https://github.com/zxing-js/browser) и [перечнем форматов ZXing](https://github.com/zxing-js/library/blob/master/src/core/BarcodeFormat.ts).
- QR принимается только в трёх случаях: чистый валидный EAN/UPC, GS1 element string `01` + GTIN-14, либо HTTPS GS1 Digital Link вида `https://id.gs1.org/01/{GTIN-14}`. Произвольные ссылки, текст с вложенным длинным числом и неподдерживаемые форматы отклоняются. URL не открывается и не передаётся серверу для fetch.
- После первого валидного распознавания сканер останавливает цикл и поток камеры. Повторы того же кода в течение одного события подавляются; один код создаёт один поисковый запрос.
- Отказ камеры оставляет доступными загрузку изображения и ручной ввод. Закрытие, уход со страницы и переход приложения в фон останавливают поток. Позднее разрешение камеры после закрытия тоже останавливается.
- Добавлены локальные unit- и браузерные тесты, команда `npm.cmd run test:t07`; `npm.cmd run check` теперь проверяет клиентские модули.

## Ограничения и физические устройства

Автоматические проверки не подтверждают работу физической камеры. Перед производственным заявлением отдельно проверить:

- Android Chrome: задняя камера, фокус на мелком EAN, разрешение/запрет камеры, сворачивание вкладки, загрузка из галереи, EAN-8/13, UPC-A/E и GS1 QR.
- iOS Safari: HTTPS-разрешение камеры, выбор задней камеры, возврат из фона, загрузка HEIC/фото из медиатеки и все поддержанные форматы. HEIC сейчас не принимается; нужен JPEG/PNG/WebP.
- Реальные упаковки с бликами, цилиндрической поверхностью, низким контрастом и повреждённым кодом. Наличие fallback не гарантирует чтение каждого снимка.

Нативный `BarcodeDetector` различается между браузерами, поэтому без полного списка форматов намеренно используется ZXing. Старые ограничения WebRTC/iOS и качество автофокуса остаются свойствами устройства и браузера.

Общая регрессия T01 остаётся красной по четырём ранее известным дефектам вне T07:

- T01-09: оценка всей формулы по active-only списку.
- T01-10: источник отбрасывает карточку точного EAN без INCI; сканирование кода работает, но такая карточка может не появиться до T08.
- T01-11: профиль по умолчанию не нейтрален.
- T01-12: старый тест проверяет центр сканера до прокрутки и получает `null`/перекрытие фиксированной кнопкой. В T07 реальные клики со штатной автопрокруткой и размеры 360/390/412 проходят; переработка мобильной компоновки не выполнялась.

Эти проверки не отключались, соответствующие задания не выполнялись.
