# T17. История с происхождением результата

## Что изменено

- `public/history-snapshot.js` — добавлен единый формат снимка анализа `1.0` для клиента и сервера. Снимок содержит дату, товар, выбранную формулу, источник, рынок/версию, полноту, подтверждения, версии алгоритма и справочника, а также фактически показанный результат.
- `public/app.js`, `src/server.js` — локальная и серверная история создаются через один сборщик. Неуспешный ответ, персональный разбор с политикой `session_only` и запись без завершённого результата не сохраняются как успешный анализ.
- `public/history.js`, `public/profile.js` — открытие показывает сохранённый результат и его версию без запроса на пересчёт. Для нового расчёта добавлена отдельная кнопка «Повторить анализ»; новый результат добавляется отдельной записью, исходная не изменяется.
- `public/history.html`, `public/profile.html`, `public/styles.css` — подключены модульные сценарии и доступная кнопка повторного анализа без изменения общей компоновки страниц.
- `tests/t17-history.test.js`, `audit/t17-history.test.py` — добавлены модульные, HTTP и браузерные проверки T17.
- `package.json` — добавлена команда `npm.cmd run test:t17`; новые сценарии включены в синтаксическую проверку.

## Политика хранения

- Фото, миниатюры, `data:` URL и иные медиаполя в снимок не попадают.
- Профиль и использованные персональные поля не сохраняются без отдельного согласия. Для таких анализов продолжает действовать режим `session_only` из T14.
- При чтении локальной истории выполняется узкая privacy-миграция: из старых записей удаляются ранее сохранённые профиль и медиаданные, сам результат и состав остаются.
- Старые записи без снимка открываются с явной оговоркой о неизвестной версии правил и неполном происхождении.
- Маршруты, владелец записей, обязательная авторизация и существующее удаление истории не изменены.

## Ограничения

- Явного согласия на хранение части персонального профиля в приложении пока нет, поэтому T17 сохраняет безопасный нейтральный снимок без профиля.
- У старых записей невозможно восстановить версии правил, справочника и источника, если они не были сохранены изначально; интерфейс не подставляет их задним числом.
- Сохранение фото в истории намеренно не реализовано. Существующий механизм удаляет всю историю пользователя; отдельное удаление одной записи не добавлялось, поскольку это не входило в T17.
