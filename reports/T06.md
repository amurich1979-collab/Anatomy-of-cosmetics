# T06: фото, камера и подтверждение состава

Дата: 28.09.2026. Выполнен только T06. Авторизация, Telegram, деплой, маршруты API и экспертные правила не изменялись. Существующие изменения рабочей копии сохранены.

## Изменения

- `public/app.js`: состояния accepted, reading, label_type, clarification, confirmation, analysis, confirmed, error. Фото больше не запускает анализ без подтверждения. Режимы unknown/mixed, недостаточно подтверждённых позиций и низкая уверенность OCR требуют нового снимка/уточнения.
- Для состава используются только entries со статусом confirmed. Исключённые позиции перечислены пользователю, формула помечается partial. Редактирование распознанного текста повторно запускает серверную очистку и требует нового подтверждения.
- Для лицевой этикетки показаны найденный кандидат и источник состава. Это предложение для сверки с упаковкой, не автоматическое подтверждение идентичности товара. Текущий поиск возвращает одного кандидата; новый поисковый движок в T06 не добавлялся.
- OCR confidence и доступные координаты слов/строк сохраняются в памяти текущего задания. Confidence передаётся отдельно как ocrReadability; координаты не отправляются внешним источникам и удаляются при очистке фото. Это показатель движка, не вероятность правильного определения товара.
- Проверяются MIME, размер до 15 МБ, декодирование изображения и ограничение 40 Мп. Поддерживаются JPEG, PNG, WebP. SVG, HEIC, пустые/повреждённые файлы не передаются OCR.
- Новое фото отменяет прежнее задание, запрос распознавания текста на сервер и активный Tesseract worker. Ответы устаревших операций игнорируются, включая завершение анализа. Object URL освобождаются при замене, очистке и уходе со страницы.
- Камера открывается отдельной кнопкой. Отказ предлагает загрузку файла; закрытие, снимок и уход со страницы останавливают tracks. Позднее разрешение камеры после закрытия не возобновляет поток.
- `public/index.html`: кнопка камеры вместо label, доступный status, явные кнопки подтверждения, блокировка кнопок до готовности.
- `public/styles.css`: статус остаётся в потоке документа и переносит длинный текст, не перекрывая фото. Общий дизайн не переделывался.
- `src/server.js`: существующий `/api/photo/resolve` дополнен полем entries из локального cleaner. Старые поля сохранены.
- `package.json`: команда `test:t06`.
- `audit/t06-photo.test.py`: браузерные проверки жизненного цикла фото и камеры.
- `audit/t01-browser-regressions.py`, `audit/t02-browser.test.py`, `audit/t03-browser.test.py`: повреждённый PNG fixture заменён валидным; T02/T03 используют актуальный mode:composition, entries и явное подтверждение. Проверки ошибок и владения составом не удалялись.

## Известные ограничения

Браузерные тесты подменяют OCR и внешние источники. Они проверяют безопасность переходов и запросов, но не доказывают качество чтения реальных упаковок или работу физической камеры Android/iOS. Tesseract остаётся существующим движком, языковые файлы требуют загрузки; фото внешнему AI-провайдеру не отправляется. Порог confidence 60/100 является консервативной эвристикой, не калиброванной медицинской оценкой. При отсутствии confidence значение остаётся неизвестным.

Редактор обрезки/поворота не добавлялся, собственный OCR или алгоритм восстановления повреждённой формулы не создавался. Для нечитаемых/смешанных этикеток предлагается отдельный более чёткий снимок. Поддержка HEIC и физические мобильные устройства требуют отдельной проверки.

Общая команда `npm.cmd run test:regressions` остаётся красной из-за четырёх прежних дефектов вне T06:

- T01-09: оценка всей формулы по active-only списку.
- T01-10: потеря карточки по EAN без состава.
- T01-11: ненейтральный профиль по умолчанию.
- T01-12: перекрытие сканера фиксированной кнопкой при 390 px.

Эти проверки не отключались и соответствующие задания не выполнялись. В частности, маркировка partial в T06 не исправляет экспертное оценивание неполных формул: это остаётся отдельным риском T01-09.
