# T02 — Безопасное поведение при сбое анализа

## Что изменено

- Обе точки запуска анализа в `public/app.js` используют один серверный путь.
- HTTP-ошибка, потеря сети и тайм-аут больше не запускают локальный упрощённый анализатор.
- При отказе старый отчёт заменяется явным сообщением об ошибке без оценок и советов.
- В сообщении доступна кнопка «Повторить анализ».
- Состав, название и загруженное фото остаются на странице для повторного запроса.
- Неуспешный запрос не записывается в локальную историю как успешный анализ.
- Для зависшего запроса добавлен клиентский тайм-аут 20 секунд.

Маршруты API, серверный анализатор, авторизация, Telegram, деплой и данные не изменялись.

## Проверки

```powershell
npm.cmd run test:t02
npm.cmd test
npm.cmd run check
python audit/t01-browser-regressions.py
```

`test:t02` использует локальные API-моки и проверяет:

- ручной запрос: успешный отчёт -> 503 -> повтор -> новый серверный отчёт;
- отсутствие ложной оценки и записи истории при offline;
- завершение зависшего запроса по тайм-ауту;
- сохранение фото и состава после ошибки анализа, запущенного из OCR-сценария.

Мок OCR обозначает только границу браузерного сценария и не является проверкой
реального распознавания изображения.

## Ограничения

- T02 не исправляет качество OCR, `mode:unknown`, принадлежность состава товару,
  профиль по умолчанию и мобильную компоновку: это отдельные T03–T15.
- Клиент не пытается вычислять экспертный отчёт без сервера. Пользователь должен
  повторить запрос после восстановления соединения.
- Текущий 20-секундный тайм-аут фиксирован для пользовательского приложения;
  тестовый контур уменьшает его через отдельную настройку страницы.
