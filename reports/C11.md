# C11. Персональный вывод

Дата проверки: 2026-10-05.

Статус: **реализовано на инженерном уровне; предметное покрытие ограничено текущими одобренными данными**.

## Выполнено

- Персональный результат разделён на независимые части: соответствие выбранной цели, предосторожности и установленные ограничения.
- Ограничение больше не удаляет общий разбор формулы и справочные основания. Оно только запрещает положительный призыв начать применение.
- Предосторожность может сосуществовать с независимым подтверждённым соответствием цели; безопасность и переносимость при этом не объявляются установленными.
- Пропущенные параметры профиля связаны с конкретными зависимыми выводами через `missingInputsByConclusion`, а не блокируют весь отчёт.
- Сохранён приоритет медицинской классификации, сообщённой прошлой реакции на продукт и точного/однозначного совпадения INCI с сообщённым аллергеном.
- Свободный текст о состоянии кожи не преобразуется в диагноз или противопоказание.
- Персональные выводы представлены разрешаемыми Claims в `formulaAssessment.personalFit`; все ссылки проверяются валидатором контракта.
- При любом заполненном поле профиля действует прежний режим `session_only`: автоматическая запись в историю не выполняется, явная запись такого результата отклоняется.
- Версия алгоритма обновлена до `analyzer-v8-personal-fit`.

## Правила приёмки

| Требование | Результат |
| --- | --- |
| Один продукт для разных профилей даёт разные выводы по конкретным основаниям | Выполнено: тестируются нейтральный профиль, точный аллерген, прошлая реакция, медицинский класс и независимая цель |
| Соответствие цели, предосторожность и ограничение разделены | Выполнено в `personalization` и `formulaAssessment.personalFit` |
| Одно предупреждение не уничтожает независимую справочную информацию | Выполнено; `goalAssessments` и общие системы формулы сохраняются |
| Пропуск поля ограничивает только зависимый вывод | Выполнено через `missingInputsByConclusion` |
| Нет гарантии безопасности и схем лечения | Выполнено; `safetyEstablished=false`, `applicationAdviceAllowed=false` |
| Нет произвольных противопоказаний | Выполнено; ограничения создаются только защитными правилами с явным происхождением, свободный текст остаётся предосторожностью |
| Персональные сведения не начинают сохраняться автоматически | Выполнено; политика хранения не менялась и остаётся `session_only` |

## Ограничения

- Production-база сейчас не содержит Claims с полным сочетанием `approved + verified + context_matches + conclusionSupported`; поэтому реальный пользователь не получает неподтверждённый статус `potential_fit`. Синтетические одобренные записи существуют только в тестах политики.
- Точный INCI и однозначные aliases используются для аллергена; fuzzy-совпадения и предполагаемая перекрёстная реакция не создают ограничение.
- Инженерные тесты не заменяют содержательную проверку химиком-технологом и медицинским специалистом.
- Официальная справка FDA об аллергенах используется только как общий контекст и не является заключением по конкретному продукту или требованиям РФ: https://www.fda.gov/cosmetics/cosmetic-ingredients/allergens-cosmetics.
- UI-вывод нового контракта относится к C12 и в рамках C11 не изменялся.

## Итог

C11 выполнено в заявленных границах. Персональная логика стала зависимой от конкретных оснований, не скрывает независимый общий анализ и не повышает неопределённость до медицинского вывода. Хранение персональных данных не расширялось.
